# *hp*-VPINN for inverse hydraulic parameter recovery in unsaturated porous media

This repository contains the implementation of the *hp*-variational
physics-informed neural network (*hp*-VPINN) framework for inverse modelling
of horizontal capillary flow, developed alongside the manuscript:

<!--
> B. A. Tourn, S. Palavecino, P. A. Kler, G. S. Gerlero —
> *Inverse parameter estimation of horizontal capillary flow in porous media with hp-variational physics-informed neural networks* -
> *Transport in Porous Media*, 2026 (under review).
-->

The framework recovers unknown hydraulic parameters from sparse, noisy
moisture-content profiles by embedding the Boltzmann similarity
transformation of the Richards–Richardson equation into a differentiable
neural network architecture trained with JAX.

## What this repository contains

The four cases of the manuscript, with the *hp*-VPINN formulation (`-es` and
`-gb` weighting):

| Case | Problem | Diffusivity model | Data file |
|---|---|---|---|
| 1 | Grenoble sand, synthetic, 1 % and 2 % noise | van Genuchten | `data_grenoblesand.dat` |
| 2 | Whatman No. 1 paper, experimental | van Genuchten | `data_vangenuchten.dat` |
| 3 | Whatman No. 1 paper, experimental | LETd | `data_letd.dat` |
| 4 | Grenoble sand, synthetic, 1 % noise | Brooks and Corey | `data_brooks_corey.dat` |

The data files of Cases 1 and 4 hold the noise-free reference curve
(columns: similarity variable, moisture content); the noise and the train/test
split are generated by the search drivers from fixed seeds (see
[Reproducibility](#reproducibility)). The experimental files carry a third
column with the standard deviation of each point.

**Not included.** The collocation PINN configurations of the manuscript were
run with a development version of `Frontx`, which is not part of this
repository; their results are available upon reasonable request, and the search
drivers contain only the *hp*-VPINN backend. The conventional-inversion scripts
(`conventional/`) need the upstream package
[`gerlero/frontx`](https://github.com/gerlero/frontx), which `uv sync` does not
install; without it they stop with `ModuleNotFoundError`. They follow the
reference example of upstream commit `e04d264` (2026-09-18).

`results/` has the same layout the scripts write to:
`results/hp_vpinn/{results_<study>,tables,Figures,sensitivity_*,quadrature_check_*}`,
`results/multistart/` and `results/conventional/`. `Figures/` contains only
figures; the LaTeX tables, `winners.json`/`winners.csv` and the machine-readable
summaries are in `tables/`. The repository holds the recorded
hyperparameter-search results, the generated tables and the summaries of the
supplementary analyses. The large outputs (final runs with their training
histories, multi-start runs, Optuna databases, figures) are archived on Zenodo
with the release; extract that archive inside `results/` so that
`results/hp_vpinn/final_runs/<tag>/` exists. The location of the results and of
the data can be changed with the environment variables `HPVPINN_RESULTS` and
`HPVPINN_DATA` (see `src/hpvpinn_capillarity/paths.py`).

## Installation

The project uses [`uv`](https://docs.astral.sh/uv/) (Python >= 3.13):

```bash
git clone https://github.com/btourn/hpvpinn-capillarity.git
cd hpvpinn-capillarity
uv sync
source .venv/bin/activate        # Linux / macOS
```

`uv sync` installs the package `hpvpinn_capillarity` in editable mode with the
versions of `uv.lock`. All commands below are run from the repository root with
this environment active. Importing the package enables 64-bit precision in JAX,
as in all the runs of the manuscript. The final runs of the manuscript were
produced on a laptop CPU (Intel Core i7-1355U, no GPU) with Python 3.14.4,
JAX/jaxlib 0.9.0.1; each run records its own environment in `record.json`.

## Reproducing the results

The pipeline of each case has four stages.

**1. Hyperparameter search.** One Optuna study per case, noise level and
weighting schedule (`gb`: `--warmup-epochs 0 --transition-epochs 20000`; `es`:
`--warmup-epochs 200000 --transition-epochs 0`). The studies of the paper have
250 trials and were run as five workers sharing one SQLite study (50 trials
each); see [`slurm/`](#cluster-launchers).

```bash
python -m hpvpinn_capillarity.hpo.search_grenoblesand --model hp_vpinn --noise-level 0.01 \
    --warmup-epochs 0 --transition-epochs 20000 --n-trials 50
python -m hpvpinn_capillarity.hpo.search_letd --model hp_vpinn --warmup-epochs 0 --transition-epochs 20000
```

Results go to `results/hp_vpinn/results_<case>_<es|gb>[_<n>pct_noise]/`.

**2. Selection of the winners.**

```bash
python -m hpvpinn_capillarity.hpo.postprocess --model hp_vpinn --case letd --es-or-gb gb
python -m hpvpinn_capillarity.hpo.postprocess --model hp_vpinn --trial-counts
python -m hpvpinn_capillarity.hpo.postprocess --model hp_vpinn --winners
```

`--winners` writes `winners.json` (in `results/hp_vpinn/tables/`), which the final-run scripts read.

**3. Final runs.** The selected configuration is trained from ten new
initialisation seeds (1000-1009) and the ensemble is reported.

```bash
python -m hpvpinn_capillarity.final_runs.grenoblesand --noise-level 0.01
python -m hpvpinn_capillarity.final_runs.vangenuchten
python -m hpvpinn_capillarity.final_runs.letd
python -m hpvpinn_capillarity.final_runs.grenoblesand --noise-level 0.01 --n-seeds 2 --epochs 2000   # smoke test
python -m hpvpinn_capillarity.final_runs.grenoblesand --noise-level 0.01 --aggregate-only            # figures from saved seeds
```

`--arch "W=16,L=2,act=tanh,Nel=30,p=5" --schedule gb` bypasses `winners.json`.
Outputs are written to `results/hp_vpinn/final_runs/<tag>/`, `results/hp_vpinn/Figures/`
(figures) and `results/hp_vpinn/tables/` (tables, curves and summaries). Case 4 has
a search driver but no final-run script.

**4. Figures, tables and supplementary analyses.** Modules are run with
`python -m hpvpinn_capillarity.<module>`.

| Item of the manuscript | Module |
|---|---|
| Winners and ranked-trial tables, diagnostic figures (SI) | `hpo.postprocess` |
| Wetting-profile figure (main text) | `final_runs.combined_profiles` |
| Early-stopping rule (main text) | `analysis.early_stopping` |
| Multi-start over the initial parameters (SI) | `analysis.multistart` |
| Quadrature convergence check (SI) | `analysis.quadrature_check` |
| Noise realisation and training-data density (SI) | `analysis.sensitivity_noise_density`, then `analysis.postprocess_sensitivity` |
| Conventional inversion and forward check with the exact solver (SI) | `conventional.benchmark`, `conventional.forward_check_bridge`, `scripts/rerun_forward_check_tight.sh` (need `frontx`) |

Main-text Figures 4-6 and the bounds-test figure of the SI are not generated by
scripts of this repository.

### Cluster launchers

`slurm/` holds the SLURM scripts of the runs: `submit_all_<case>.sh` submits
the workers of every (noise level, schedule) combination of a case (five workers
per study, 250 trials in total) and `slurm_run_hparam_<case>.sh` is the job
script. The `run_hparam_*.sh` files are earlier single-job scripts (150 trials,
one schedule) and do not reproduce the studies of the paper; use `submit_all_*.sh`
for that. The scripts change to the repository root themselves and use its
`.venv`; they keep the cluster-specific settings of the original runs (partition,
`v3-20cores` constraint, time and memory), which you may need to adapt:

```bash
bash slurm/submit_all_grenoblesand.sh --model hp_vpinn --dry-run
```

## Applying the framework to a new dataset

The recommendations below summarise the protocol of the manuscript and the
evidence in its Discussion and Supplementary Information (SI). They describe
what was done and observed for the four cases; the thresholds were fixed
empirically and their transfer to other data was not tested. The simplest
route is to copy `hpo/search_<case>.py` and `final_runs/<case>.py` of the
closest case and adapt the data, the constants and the model.

**Scope.** The framework applies to one-dimensional horizontal flow with
constant boundary and initial conditions, where the Boltzmann transformation
reduces the problem to an ODE in the similarity variable. It does not apply
directly to gravity-driven or multidimensional flow, time-dependent boundary
conditions, or heterogeneous media. The data loss assumes independent
measurement errors with known standard deviations.

**1. Choose the constitutive model.**
`constitutive_model.py` provides van Genuchten, LETd and Brooks and Corey
diffusivities, with parameters declared as fixed, free or bounded.
- Compare candidate models with an exact forward solver on the same data and
  split, where one is available (manuscript, "Model adequacy"). A misfit above
  the noise level that is independent of the split and of the network points to
  an inadequate model: in Case 2 the van Genuchten fit stays above it
  ($\chi^2_\nu$ about 1.6-2.1), whereas LETd (Case 3) reaches about 0.9-1.0.
- Do not read a low $\chi^2_\nu$ as evidence of a better model. The `-es`
  solutions of Case 2 fit the data better but, inserted into the exact solver,
  do not satisfy the equation for the parameters they report.
- Parameters that reproduce the data equally well can differ strongly. Compare
  the recovered $D(\theta)$ and not only the parameters; they differ most
  where the data carry little information, at the dry end.

**2. Choose the parameter ranges and the initial values.**
- The initial values are fixed in the search drivers, so the ranking of
  architectures is conditional on them. Run several starting points
  (`analysis/multistart.py`). In Case 1, about 40-50 % of the starts did not
  converge, and the non-convergent runs are flagged by `obj`.
- Bounds that exclude the true value are not detected by the fit: qualified
  runs ended on or next to the bound with errors of 12-240 % in a parameter.
  Treat an estimate within a few per cent of a bound as not determined and
  relax the bound.

**3. Choose the architecture and the hyperparameters.**
- Search space of the paper (960 combinations): hidden layers {1, 2, 3}, width
  {8, 12, 16, 24, 32}, activation {tanh, sigmoid, GeLU, Swish}, elements
  {10, 20, 30, 40}, polynomial degree {3, 4, 5, 6}; quadrature order 24 and
  $\lambda_{bc}=10$ fixed. Small networks were preferred.
- Optuna TPE sampler (multivariate, grouped, 25 initial random trials),
  250 trials, 200 000 steps per trial without early stopping, 20 % of the points
  held out. The objective is $\chi^2_{\nu,\mathrm{train}} + \chi^2_{\nu,\mathrm{test}}$.
- A trial is *admissible* if the weak-form residual re-evaluated at a held-out
  quadrature order ($Q_{\mathrm{eval}}=40$) is below $10^{-5}$, *calibrated* if
  `obj` < 4, and *qualified* if both hold. The winner is the combination with
  the most qualified runs, not the single best trial.
- The physics loss at the training nodes can underestimate its value at held-out
  nodes (a factor of about 30 at $Q=24$ in Case 1), so judge enforcement on the
  held-out evaluation and on the strong-form residual
  (`core/strong_form_residual.py`).

**4. Interpret the convergence.**
- In Case 1 the data loss falls below the nominal noise level within about
  1.1-1.4 x 10^3 steps, when the trainable parameters are still at their initial
  values; the parameter error stays near 100 % until 3-6 x 10^3 steps. The
  parameters are determined only once the physics loss starts to act.
- Physics loss is oscillatory. The early-stopping indicator of the paper is its
  exponential moving average ($\beta_s = 0.99$, $\tau_{stop} = 5\times10^{-8}$,
  window $10^4$). It worked within the tested range in Case 1 but not in Case 3.
- A single run is not sufficient. Use several seeds and starting points, the
  acceptance criteria above, and a forward check with an exact solver where one
  exists. A calibrated fit does not certify the parameters: in Case 1 the data
  constrain a ridge in the $(K_s/\alpha, m)$ plane and not a point.

## Reproducibility

Training is deterministic for a fixed seed on a fixed hardware and software
configuration. Exact bitwise reproducibility across platforms cannot be
guaranteed, because floating-point reductions in JAX/XLA are not
order-invariant under parallel execution; results are reproducible in a
statistical sense (ten seeds per selected configuration). On the laptop that
produced the final runs, a fresh clone of this repository (environment from
`uv.lock`, Python 3.13) reproduced seed 1001 of each of the five final runs of the
manuscript (Case 1 at 1 % and 2 % noise, Case 2 `-es`, Case 3 `-es` and `-gb`;
200 000 epochs each): `reference.npz`, `history.npz` and `model.eqx` are
byte-identical to the stored files, and the arrays of `curves.npz` are identical
(the stored `curves.npz` of four of these runs predate two arrays, `residual` and
`residual_phi_nd`, that the code writes now). Repeated runs gave identical files.
This was checked for one seed per final run and on one machine; the stored run of
Case 3 `-es` was obtained with the configuration selected at the time, so it is
reproduced with `--arch` and not with `winners.json`. The Optuna searches
used five parallel workers on a shared database, so the order of the trials,
and therefore the sampler state, is not reproducible bit by bit.

Seeds: noise seed 42 in Case 1 and split seed 7 in all cases (SI, "Notes on
reproducibility"); the noise seed of the noise-realisation study is 42 + r,
r = 0..24; the initialisation seed of a search trial is its Optuna trial
number; the final runs use seeds 1000-1009.
`PROVENANCE.md` lists the source commits and the sha256 of every file copied
from the development workspace.
